# design.md：具体怎么设计并保持统一

**回答**：布局、尺寸、颜色、字体、间距、圆角、边框、阴影、响应式、主题、动效、图标。
**不回答**：业务规则（prd.md）、视觉方向与气质（visual.md）、页面级细节（page-specs.md）。

**这是所有具体数值的唯一出处。** 其它文档一律用「见 design.md §X」引用，不复制数值。

## 每节写什么

- **1 令牌总表**：把 2–10 节里所有可复用的值列成一张表（名字 → 值 → 用在哪）。
  有令牌体系的（CSS 变量 / Tailwind theme / 设计工具变量）写清变量名，让代码和设计工具对得上。
- **2 布局与栅格**：容器最大宽度、左右边距、列数与间距、内容与全宽区块的区别。
- **3 间距尺度**：基数（如 4/8）与允许出现的档位；写明「区块之间」「区块内」「控件之间」各用哪档。
- **4 颜色**：用语义命名（background / foreground / primary / muted / accent / border / destructive / 强调色……），
  逐个写 **浅色值 + 深色值 + 使用场景**。正文与背景的对比度目标写在这里。
- **5 字体与字号表**：`用途 | 字号 | 行高 | 字重 | 字距 | 对应类名`。
  每个字号必须说明用在哪（页面主标题 / 区块标题 / 卡片标题 / 正文 / 辅助 / 订单号等），只给数值等于没写。
  金额、数量、编号类文本统一启用等宽数字，避免数字变化时跳动。
- **6 圆角 / 边框 / 阴影**：分档（小 / 中 / 大 / 全圆），写清每档用在哪；阴影要有「层级语义」（浮层 > 卡片 > 内嵌）。
- **7 响应式**：断点值 + **每一档的行为差异**（列数变化、导航形态变化、哪些内容隐藏或折叠）。
  「自适应」不是规格，写清在哪一档发生什么。
- **8 主题**：支持浅 / 深色与否；切换方式与记忆方式；不允许出现「深色下反色」的临时处理。
- **9 动效**：允许动画的位置、时长区间、缓动曲线、入场动效的触发时机。
  必须写明 **`prefers-reduced-motion` 下的降级行为**；连续自动播放类的动效要说明速度、暂停条件与是否提供控件。
- **10 图标**：图标库、默认尺寸、与文字的对齐基线、可点击图标的最小命中区域。
- **11 可访问性底线**：对比度、焦点可见、键盘可达、命中区域尺寸、图片替代文本、表单标签关联。

## 写作要点

- 一个语义只对应一个值。发现同一语义出现两个值时，改令牌而不是在组件里打补丁。
- 组件里不写原始色值 / 原始调色板色（如 `bg-blue-500`），只用语义令牌。
- 字号与间距要给出可复用的名字或类名，让页面层能直接引用而不是重新估。
- 令牌表随设计演进更新，并升版本；旧值不要留在文档里造成第二套事实。

## 常见漏项

- 色值散落在组件里，文档里的令牌没人用。
- 字号表只有数值，没有「用在哪」，于是每个人各挑一个。
- 响应式只写「自适应」，没写每档的具体变化。
- 只有浅色主题，深色靠反色硬凑。
- 动效时长随意，没写 reduced-motion 降级。
- 间距靠手感填魔法数字，没有尺度表。

## 验收清单

- [ ] 所有可复用数值都在令牌总表里，且只有一处定义。
- [ ] 每个字号都能从「用途」反查到，反之亦然。
- [ ] 每个语义色都有浅色值、深色值和使用场景。
- [ ] 响应式写清了每一档的具体变化。
- [ ] 动效章节包含 reduced-motion 的降级行为。
- [ ] 可访问性底线是可检查的量化条目，不是口号。
