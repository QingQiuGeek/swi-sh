## 每节写什么

### 1 分层模型

从下往上四层，**依赖单向，下层不知道上层存在**：

```text
Tokens → Components → Blocks → Pages
```

| 层 | 位置 | 职责 | 禁止 |
| --- | --- | --- | --- |
| Tokens | 全局样式 / 主题文件 | 语义色、圆角、阴影、字体变量 | 组件里写原始色值 |
| Components | 组件库目录 | 纯通用原子组件 | 写业务文案、发请求、读服务端数据 |
| Blocks | 业务区块目录 | 有业务语义、可跨页面复用的一块 UI | 自己发请求 |
| Pages | 路由目录 | 取数、鉴权、路由、编排 Block | 写视觉细节、写原始色值 |

按需补充中间层：只服务于单个页面的编排层、全站骨架层（头尾/容器）、带交互状态的重型区块层。
**判断归属的一句话规则**：这段 UI 换一个页面还能用吗？能 → Blocks；只在一个页面用 → 页面编排层。

### 2 目录结构

用代码树列出真实目录，**每个目录后面用一句话写职责**。结构要能一眼看出上面四层的边界。

### 3 需要的组件库组件

列出立刻要用的组件与「用在哪」；其余用到再加，不要一次装全。
统一从官方 registry 安装，不要手抄源码。

### 4 组件规范

**强制规则**（违反即不合格）：

- `className` 只做布局（间距、宽高、对齐），不改组件库定义的配色与字体。
- 只用语义色令牌，不写原始色值。
- 纵向堆叠用 `flex flex-col gap-*`，不用 `space-y-*`。
- 图标不额外加尺寸类，由组件负责；组件内图标用组件库约定的属性表达位置。
- 覆盖层（弹窗、抽屉、气泡）不手写 `z-index`，由组件自己管理。
- 状态样式用组件库约定的数据属性（`data-*` / `aria-invalid` / `disabled`）触发，不自己拼类名。
- **不直接改组件库生成的源码**。要定制就在自己的组合组件里适配；确需改源码时，先评估对全部调用点的影响。

**自定义组件约定**：

- 文件 kebab-case，组件 PascalCase，一个文件一个主组件。
- props 显式声明并导出类型；不要把无约束的 `...rest` 透传到有语义的容器上。
- 变体用组件库同一套机制定义（如 `cva`），风格与组件库源码保持一致。
- `"use client"` 只加在确实需要交互的叶子组件上，**不要加在页面或 Section 上**，否则整棵子树失去服务端渲染。
- 服务端组件不得引入只用客户端的 API（`useState`、`useEffect`、事件处理）。

**包装组件库组件时的必测项**（容易漏）：包装后透传的 `data-*` 标记可能覆盖组件内部用于样式选择器的标记，
导致焦点环、报错态、禁用态样式失效。包装完必须实测：**聚焦态、报错态、禁用态、键盘操作**，并和未包装的同类控件对比。

### 5 Block 规范

- 一个 Block 一个文件，导出一个组件。
- **Block 不发请求**：数据由 Page 取好通过 props 传入。这样同一个 Block 在首页、列表、详情都能复用，SSR/CSR 都成立。
- Block 不读全局 store、不读服务端数据模块；需要的数据全部来自 props。

### 6 复用规则

- 两处结构相似且**变化原因相同**才抽象；只是长得像就复制。
- 抽象时把变化点做成 props 或变体，不要把具体业务写死在通用组件里。
- 反向：发现同一个块在第三处出现时，回头抽象，而不是继续复制。

### 7 状态规范

- **数据四态**：加载 / 空 / 错误 / 成功，每态给出呈现方式（骨架屏、空态组件、错误重试）。
- **鉴权态**：未登录 / 已登录 / 无权限，分别说明页面表现与跳转去向。
- **表单态**：
  - 提交中要禁用提交按钮并给出进行中指示，防止重复提交。
  - 提交失败保留用户已填内容，不清空。
  - 服务端只返回业务码：**能唯一归属到某个字段的码贴到该字段，其余集中为表单级提示**。
  - 校验规则前后端共用同一份定义（如同一套 schema），不要两边各写一遍。

### 8 导航交互模式

逐条写清本项目实际用到的模式与实现要点，例如：

- **SPA 路由导航**：站内跳转用路由组件，不用裸 `<a>`；不用 hash 路由。
- **分区滚动导航**：Section 的 id 常量**集中定义在一处**，Header、侧边轨、移动端菜单共用同一份，避免三处各写一遍而不同步；
  Section 需要滚动偏移补偿（吸顶头高度）；高亮当前分区由滚动位置驱动。
- **侧边 Tab 导航**：选中态由路由决定，不额外维护一份状态。
- **语言切换**：URL 带语言前缀时，切换要替换前缀而不是跳到首页；保持当前路径与查询参数。
- **弹窗 / 抽屉**：切换后要能回到原意图（如登录成功后回到刚才要进的表单）。
- **移动端导航**：折叠形态、命中区域、打开后是否锁滚动、关闭方式。

每条都要写「为什么这样做」和「不要怎么做」，否则后面容易被改回去。

### 9 路由实现规则

- 路由形态（要不要语言前缀、动态段命名、是否需要 middleware 处理根路径）。
- **取数位置**：页面级数据用服务端取数；只有交互后的更新才走客户端请求。
- 客户端请求统一走一个封装（解包统一响应体、统一处理未登录/过期），不要在组件里各写一份 fetch。
- 提交成功后如何刷新服务端数据（刷新当前路由 / 重新取数）。

### 10 通用布局模式

页面骨架（头 / 内容 / 尾）、容器宽度与内边距、区块之间的垂直节奏、内容型页面与全宽区块的区分。

## 常见漏项

- 目录结构里没有「每层职责」，后面新人随便放。
- 只写了「用组件库」，没写包装组件后要重测焦点/报错态。
- 导航交互三处各写一份常量或各实现一遍，最终不同步。
- 状态只写成功态，空态与错误态后面临时补。
- 没有「取数位置」的约定，服务端组件和客户端请求混用。
