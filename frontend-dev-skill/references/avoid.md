# avoid.md：什么不要做

**回答**：禁止的视觉风格、UI / 组件 / 布局 / 内容 / 交互反模式，以及 AI 常见问题。
**不回答**：正向规范（分散在 prd / visual / design / ui-patterns / page-specs）。

**写法要求**：每条都要写「错在哪 → 改成什么」。只列禁止项不给替代方案，等于没写。

## 每节写什么（附典型条目）

### 1 视觉风格

- 用模板化的默认美学（默认蓝紫渐变、发光边框、无差别圆角卡片）→ 按 visual.md 的方向与 design.md 的令牌做决策。
- 用高饱和大片色块制造「设计感」→ 品牌色只作强调，正文区域保持中性。
- 为了好看牺牲可读性（浅灰文字压浅底）→ 对比度按 design.md 底线执行。

### 2 UI 反模式

- 层级混乱：所有文字差不多大、所有按钮都是主按钮 → 每屏只有一个主行动。
- 无反馈：点击后没有任何变化 → 提交中禁用 + 进行中指示；成功/失败给出提示。
- 焦点丢失 / 不可键盘操作 → 所有交互元素可聚焦、可见焦点环。
- 用颜色单独表达状态（红绿）→ 颜色 + 文字/图标双重表达。

### 3 组件反模式

- 手写基础标签绕过组件库（自造按钮、自造输入框）→ 用组件库组件与官方组合方式。
- 把按钮塞进输入框时用相对定位硬拼 → 用组件库提供的输入框组合（如 addon / group）方案。
- 复制粘贴同一段 UI 到多处 → 抽成 Block。
- 直接修改组件库生成的源码 → 在自己的组合组件里适配。
- 包装组件库组件后不重测焦点环、报错态、禁用态。

### 4 布局反模式

- 魔法数字（随手的 `margin-top: 37px`）→ 用间距尺度里的档位。
- 写死宽高导致窄屏横向滚动 → 响应式按 design.md 的断点验证到最窄档。
- 忽略断点，只测桌面 → 每个断点都实际跑一遍。
- 长文本不设溢出策略 → 明确换行、截断或撑开。

### 5 内容反模式

- 硬编码业务文案（中英文写死在组件里）→ 一律走文案字典，多语言同时补齐。
- 术语前后不一致（同一概念两种叫法）→ 在 prd.md 里定对照表。
- 占位内容（Lorem、TBD、待补充）留在交付物里 → 交付前清零。
- 只写「10 条数据」这类具体数字进用户可见文案 → 文案要么不提数量，要么由数据驱动。
- 用假数据冒充真实数据且不标注 → 明确标注为演示数据。

### 6 交互反模式

- 动画卡顿或一卡一卡（逐张跳、到头跳回起点）→ 连续匀速位移，且提供暂停（悬停/聚焦）与 reduced-motion 降级。
- 自动播放且无法停止，或抢占焦点 → 提供暂停条件，不抢焦点。
- 破坏浏览器行为（禁用回退、劫持滚动、无法用新标签打开）→ 保持原生行为。
- 弹窗关闭后丢失用户意图 → 关闭/登录成功后回到原意图。

### 7 AI 常见问题

- **自造需求**：加了没人要求的功能、配置项、「灵活性」→ 只做需求内的，其余先问。
- **过度抽象**：为一次性代码建抽象层 → 出现第三处重复再抽象。
- **顺手重构**：改了无关代码、格式、注释 → 每行改动都要能追溯到本次需求。
- **无证据宣称完成**：说「已优化」「很流畅」但没测 → 给出可复核的证据（命令输出、测量数值、截图）。
- **文档与代码不一致**：改了行为没回写文档 → 按 SKILL.md 的回写表同步，再交付。
- **只跑通正常路径**：没试失败、空数据、未登录、最窄屏幕。
- **凭记忆写框架 API**：不核对当前版本文档就下手 → 先读项目内该框架的文档/现有用法再写。
- **一次改多个模块**：出了问题无法归因 → 一次一个模块，做完先让用户验收。
