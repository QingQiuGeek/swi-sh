# page-specs.md：每个页面具体怎么搭

**回答**：每一页的 Route、内容、结构、用到的组件与 Block、核心操作、数据、状态、响应式、页面间跳转、验收点。
**不回答**：跨页通用规则（ui-patterns.md）、具体数值（design.md）、业务规则（prd.md）。

## 骨架

```markdown
# <产品名> 页面规格

> 版本：v0.1｜上游：prd.md / ui-patterns.md / design.md

## 0. 通用约定
## 1. 全局骨架
## 2. <页面名>（/{locale}/xxx）
（每页重复 2.1–2.9）
```

### 每页的模板

```markdown
### 2.1 目标
这页让用户完成什么？一句话。

### 2.2 页面结构
从上到下的区块清单（用有序列表或树），与 prd.md 的功能编号对应。

### 2.3 用到的 Components / Blocks
逐个列组件名；标注是服务端还是客户端组件，以及是否需要「登录后才可见」。

### 2.4 核心操作
表格：`操作 | 触发控件 | 行为 | 成功结果 | 失败结果`。

### 2.5 数据
数据来源（服务端取数 / 客户端请求）、字段清单、从哪个模块或接口来。

### 2.6 状态
加载 / 空 / 错误 / 未登录 / 无权限 / 提交中，各自的表现。

### 2.7 响应式
每个断点的差异：列数、导航形态、隐藏或折叠的内容、卡片宽度与间距。

### 2.8 页面间跳转
入口（从哪来）、出口（去哪、带什么参数）、返回时的状态恢复。

### 2.9 验收点
可勾选、可测的具体条目。
```

## 每节写什么

- **0 通用约定**：所有页面共用的东西——容器与内边距、区块间距、标题层级用法、错误提示位置。
  只写一次，各页不再重复。
- **1 全局骨架**：页头 / 页脚 / 悬浮工具轨 / 移动端抽屉在各页是否出现、滚动时行为（吸顶、显隐）。
- **2.x 各页**：按模板逐页写全。**首页这类多分区页面要按分区逐个写**，并说明分区的顺序与 id（供分区滚动导航使用）。

## 写作要点

- **结构用清单或树，不要写成散文**，否则实现时会产生歧义。
- 每页的验收点要能被外人独立执行（点哪里、看到什么）。
- 状态必须写全，特别是空态和错误态——它们最容易在编码时被临时糊上去。
- 跳转要写双向：不仅写「点这里去哪」，也写「从哪进来的、怎么回来」。
- 页面里用到的每个 Block 都应在 ui-patterns.md 的规范内；越界使用要在这里明确说明并回头修规范。

## 常见漏项

- 只写页面内容，没写状态与响应式。
- 验收点是「页面正常」这类空话。
- 动态路由的参数规则没写（缺参数、参数不存在时的表现）。
- 一个页面里塞了本该属于通用约定的东西，其它页面又写一遍且不一致。
- 首页分区顺序改了，但头部导航与滚动轨道的顺序没同步。

## 验收清单

- [ ] 每页都有 Route、结构、组件、操作、数据、状态、响应式、跳转、验收点九项。
- [ ] 每个验收点都可独立执行且有明确预期。
- [ ] 空态、错误态、未登录态都有明确表现。
- [ ] 页面上出现的每个 Block 都能在 ui-patterns.md 里找到规范。
- [ ] 多分区页面的分区顺序与导航顺序一致。
